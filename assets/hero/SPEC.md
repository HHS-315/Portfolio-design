# 스크롤 패럴랙스 히어로 구현 명세 (레이어 방식)

## 목표

히어로 일러스트를 4개 층으로 나눠 각각 다른 속도로 움직여 입체감을 만든다.
각 층은 **통째로 평행이동/확대만** 하므로 형태 왜곡이 발생하지 않는다.
WebGL, 셰이더, 깊이맵은 쓰지 않는다. CSS transform만 쓴다.

---

## 에셋

| 층 | 파일 | 비고 |
|---|---|---|
| 0. 하늘 | 없음 | 투명. 페이지 배경색이 그대로 비친다 (원본도 하늘이 투명하다) |
| 1. 지면 | `layer-1-ground.webp` | 지평선 아래 전체. 가려졌던 부분은 이미 복원되어 있음 |
| 2. 로켓 | `layer-2-rocket.webp` | 투명 배경 컷아웃, 무손실 |
| 3. 인물 | `layer-3-person.webp` | 투명 배경 컷아웃, 무손실 |

세 파일 모두 **3548×1774, 원본과 동일한 프레임 좌표계**다. 잘라내거나 옮기지 말고
같은 위치에 겹쳐 놓기만 하면 원본 그림이 복원된다. png 버전도 함께 들어 있다.

`layers.json` 에 아래 좌표가 들어 있다. transform-origin 에 그대로 쓴다.

```
지평선      78.01%
로켓 접지점  15.68%  86.92%
인물 접지점  27.11%  92.67%
```

**transform-origin 이 이 값이어야 하는 이유**: 지면은 지평선을 기준으로 확대해야
멀리 있는 부분은 거의 안 움직이고 가까운 부분만 커진다. 로켓과 인물은 발이 닿는
지점을 기준으로 확대해야 땅에서 뜨지 않는다. 다른 값을 쓰면 물체가 공중에 뜬다.

## 레이아웃

```
<section class="hero">          height: 220vh
  <div class="stage">           position: sticky; top:0; height:100svh; overflow:hidden
    <div class="frame">         아래 규칙 참고
      <img id="lGround">
      <img id="lRocket">
      <img id="lPerson">
    </div>
    <h1 class="copy">           오른쪽 여백에 헤드라인
```

`.frame` 은 **반드시 원본 비율(3548:1774)을 유지**해야 한다. `object-fit:cover` 를
`img` 에 걸면 transform-origin 퍼센트가 이미지 좌표와 어긋나므로 쓰지 말 것.

```css
.frame{
  position:absolute; top:50%; left:0;
  width:max(100%, calc(100svh * 3548 / 1774));
  aspect-ratio:3548 / 1774;
  transform:translateY(-50%);
}
.frame img{ position:absolute; inset:0; width:100%; height:100%; }
```

`left:0` 은 의도된 값이다. 세로로 긴 화면에서 프레임이 오른쪽으로 넘치면서
로켓과 인물이 있는 왼쪽이 항상 화면에 남는다.

## 스크롤 매핑

히어로를 지나는 진행도 `p` (0 → 1). 매 프레임 lerp 로 부드럽게 따라가게 한다.

```js
shown += (target - shown) * (1 - Math.pow(0.002, dt));
```

이동량은 `p` 에 선형으로, 확대량은 `smoothstep(p)` 에 비례시킨다.

| 층 | translateX (%) | translateY (%) | scale |
|---|---|---|---|
| 지면 | 0 → -1.5 | 0 | 1 → 1.10 |
| 로켓 | 0 → -0.5 | 0 → +1.0 | 1 → 1.02 |
| 인물 | 0 → -1.2 | 0 → +2.4 | 1 → 1.05 |

헤드라인: `translateY` 0 → -140px, `opacity` 는 p=0.45 부터 0까지 감소.

**층별 이동량의 대소 관계가 핵심이다.** 인물 > 로켓 > 지면 순으로 많이 움직여야
가까운 것이 빠르게 지나가는 것처럼 보인다. 값을 조정하더라도 이 순서는 유지할 것.

## 필수 요구사항

**성능**
- `IntersectionObserver` 로 히어로가 뷰포트를 벗어나면 rAF 루프 정지
- 스크롤 이벤트에서는 target 값만 갱신. 렌더는 rAF 안에서만
- 세 `img` 에 `will-change:transform`, `backface-visibility:hidden`
- 스크롤 리스너는 `{passive:true}`

**접근성 / 폴백**
- `prefers-reduced-motion: reduce` → 모든 transform 을 걸지 않고 정지 상태로 표시
- 헤드라인은 실제 `<h1>` 텍스트. 이미지로 굽지 말 것
- 이미지 로드 실패 시에도 레이아웃이 무너지지 않아야 함

**선명도 (중요)**
- 에셋을 **다시 인코딩하거나 축소하지 말 것.** 3548px 원본을 그대로 서빙한다.
  히어로는 레티나 화면에서 3000px 이상으로 렌더되고 거기에 확대까지 걸리므로,
  더 작은 소스를 쓰면 선화가 뭉개진다
- 컷아웃 두 장을 다시 변환해야 한다면 **반드시 무손실**로. 손실 압축은 얇은
  윤곽선 주변에 링잉을 만든다
- 투명 픽셀의 RGB 를 보존하는 도구로만 처리할 것. 알파 0 인 곳의 색을 0 으로
  미는 최적화(`pngquant --strip`, PIL `optimize=True` 등)를 거치면 브라우저가
  확대할 때 검정이 번져 가장자리에 어두운 띠가 생긴다
- `will-change:transform` 은 히어로가 화면에 있는 동안에만 걸고 벗어나면 제거한다.
  계속 걸어두면 GPU 가 예전 배율로 래스터한 비트맵을 늘려 쓰면서 흐려질 수 있다
- `image-rendering` 은 건드리지 말 것


- 세 이미지 모두 `fetchpriority="high"`, `loading="lazy"` 금지
- 셋 다 로드되기 전에는 프레임을 표시하지 않음 (부분 합성 방지)

## 완료 기준

1. 스크롤해도 로켓과 인물의 **형태가 전혀 변형되지 않는다** (평행이동·확대만)
2. 로켓과 인물의 발이 지면에서 뜨거나 파묻히지 않는다
3. 지평선이 스크롤 중에도 제자리에 있다
4. 층 사이로 흰 배경이 새어 보이는 구간이 없다
5. 히어로를 벗어나면 rAF 가 멈춘다 (DevTools Performance 로 확인)
6. `prefers-reduced-motion` 에서 애니메이션이 전혀 없다
7. CLS 0

## 하지 말 것

- 스크롤 하이재킹 (스크롤을 가로채 특정 위치로 스냅)
- GSAP / ScrollTrigger / Lenis 도입 — 위 매핑은 바닐라로 30줄이면 된다
- WebGL, 셰이더, 깊이맵 워핑 — **이전 방식이며 형태 왜곡 때문에 폐기했다**
- `.frame` 이나 `img` 에 `object-fit` 적용
- 층 순서 변경 (하늘 → 지면 → 로켓 → 인물)
